V16 REPAIR PATCH — findings from the APK screenshots and failed static audit (2026-10-09)

Confirmed failure in the previously built V16 APK
- GitHub Actions run 37932613648 successfully compiled the resources and packaged the APK, but the independent release gate failed before Android emulator tests.
- Exact error: `V13_TRANSLATION_MAP_AUDIT_MISMATCH:hospital_sleep_need_opened_tips`. The localized resource still contained a Chinese suffix after the Russian text.
- Root cause was in the styled-string replacement routine: Android XML stored part of the source text in the first styled child’s `.tail`; the routine cleared some descendant text but left that tail intact.

Repairs included in this source package
1. Clear all descendant text and tails before writing the complete Russian translation for styled string resources. Regression tests cover the exact failed resource shape.
2. Translate eleven reviewed hard-coded, user-visible DEX strings: four home-card descriptions, the Mi Fitness hand-off dialog / error text, and the earlier blood-pressure title literal.
3. Restrict generic dialog labels `取消` and `打开` to the Smali method that contains the unique app-to-Mi-Fitness prompt. This avoids changing every use of those generic words elsewhere in the app.
4. Decode/rebuild the V8 `classes.dex` source and compare all Smali files. The comparison permits only allow-listed string changes and mechanical `const-string` → `const-string/jumbo` widening; it rejects method, opcode, register, control-flow, or file-set differences.
5. Verify DEX checksum/signature fields and all approved translation literals in the final APK.
6. Expand Android 15 emulator diagnostics to capture original, V10.7, and candidate V16 home/device/profile tab UI XML, screenshots, and logcat for direct comparison.

Important limits
- These checks are source/package repairs and local regression tests. This package has not yet been run by GitHub Actions; the corrected APK and emulator result do not exist until that run completes.
- The empty Device/Profile screens in the user's screenshots are not yet conclusively attributed to one cause. The emulator lacks Xiaomi Mi Fitness and a real Xiaomi account/backend session, so a blank authenticated screen may not be reproducible there.
- The existing build re-signs the APK with a generated test certificate. The original Xiaomi signing key is unavailable. If Xiaomi's account/backend or another app enforces the original signing certificate, a repackaged APK cannot be made fully equivalent by resource translation alone. Do not treat a static pass as proof that Xiaomi account, authorization, wearable connection, or data sync work.

Source package only; no claim of a released/verified APK is made.
