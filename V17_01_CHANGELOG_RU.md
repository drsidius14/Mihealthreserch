# V17.01 — исправление Smali-декодера и безопасный контур проверки

## Причина выпуска

Запуск GitHub Actions V17 (`37995593924`, commit `11bd7c4f7b53f171280d556c9ace0cf147c3c9ee`) остановился на шаге локализации DEX. Фактическая ошибка:

```text
ValueError: unsupported Smali string literal '"Couldn\\\'t find a double value"': Invalid \\escape
```

`repair/v13_localize_smali.py` и `repair/v13_compare_smali.py` использовали `json.loads()` для разбора Smali-строк. Экранирование Smali не тождественно JSON: например, Smali использует `\\'` для апострофа, а JSON не разрешает такой escape. Локализатор также разбирал все `const-string` внутри метода для построения контекста, а не только те строки, которые собирался переводить, поэтому одна посторонняя строка останавливала весь процесс.

## Изменения V17.01

- Добавлен общий `repair/v17_01_smali_strings.py`: отдельный строгий декодер/кодировщик строк Smali, включая апострофы, кавычки, обратный слеш, управляющие символы, `\\uXXXX` и пары UTF-16 surrogate.
- Локализатор и строгий DEX round-trip comparator используют один и тот же codec, что исключает расхождение правил парсинга между изменением и последующей проверкой.
- Добавлен интеграционный регрессионный набор `repair/v17_01_smali_codec_selftest.py`: проблемная строка `Couldn't find a double value`, экранирование, Unicode/CJK, emoji, управляющие символы, некорректные escape-последовательности, локализация и запрет посторонних opcode-изменений.
- Старый локализаторский self-test теперь сравнивает декодированные значения, а не ищет русские/китайские символы как сырые UTF-8-последовательности в Smali-файле. Канонический writer может представить не-ASCII как `\\uXXXX`, не меняя строковое значение DEX.
- Workflow запускает новый тест до работы с APK. Он публикует V17.01 артефакты отдельно и теперь не создаёт вторую ложную ошибку эмулятора, когда APK не был собран: runtime job выполняется только если диагностический APK реально появился.

## Ограничения подписи

Workflow использует временный тестовый ключ, созданный в ходе запуска. Это нужно для проверки устанавливаемости, но не является подписью Xiaomi. APK, подписанный другим ключом, обычно нельзя установить как обновление поверх установленного приложения с другой подписью; для теста может потребоваться удалить старую копию (это может стереть её локальные данные). Не путать этот процесс с русификацией.
